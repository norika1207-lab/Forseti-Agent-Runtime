## 5. 找到並修好的一條真違規

指令：

```bash
node test/spec-v0.1.test.mjs
```

審計開始時：

```
CONFORMS           32
VIOLATES           1
NOT_IMPLEMENTED    2
NOT_CHECKABLE      3
```

那一條：

```
★  9. 不准只因啟發式分數高就擋低風險的正常工作
      VIOLATES  forseti-stop-hook.mjs:218 有沒問過閘門的 exit(2)
```

### 查出來的真相

`forseti-stop-hook.mjs:218` 那個 `process.exit(2)` 不是漏網的。它的前面有一個提早出口：

```js
if (!enforce) {
  process.stderr.write(body + '... This is an observation, not a block.\n');
  process.exit(0);
}
```

也就是說，預設是「只講不擋」，只有 owner 在 `.forseti/config.json` 開了 `enforce_declarations` 才會擋，而且有次數上限。那是 owner 2026-09-16 明確要求的（原話：「我現在要你開啟 Forseti 全自動介入你的工作，強制介入」），設計上走 config 不走改程式碼，就是為了讓覆寫留下痕跡。

真正的問題是「判準沒有跟上那個決定」：它只認 `gate()` / `g.allowed` 這一種閘門，不認 owner 覆寫那一種。

### 更嚴重的第二層

同一個判準有兩份實作：

```
test/hooks.e2e.test.mjs   AT-HOOK-R3    視窗 15 行
test/spec-v0.1.test.mjs   第 9 條        視窗 15 行
```

兩份的錯誤訊息不一樣，而且我修好第一份之後第二份照樣紅。兩份會分歧的判斷遲早會分歧，而分歧那天不會有錯誤訊息。

### 修法

抽成一份：`test/_hookgate.mjs`，兩邊都用 `ungatedExitsWhy()`。判準改成認兩種閘門：

一，`intervention.js` 的裁決（`gate()` / `g.allowed`）
二，owner 明確覆寫，而且要三件事同時在：`if (!enforce)` 這個提早出口、它後面的 `process.exit(0)`、次數上限 `cap`

第二種刻意要三件都在。只找 `enforce` 這個字不夠，把那個 if 整段拿掉之後那個字還在別的地方，判準會放行一個無條件擋人的 exit(2)。

### 反向驗證

拿掉 `forseti-stop-hook.mjs` 的提早出口（讓它變成無條件擋人）：

```
檔案確實被改了
[好] hooks.e2e 紅
[好] spec-v0.1 回報 VIOLATES 1
還原後 2a74faf3df75aeed5002505fb102ad0b4259937e30f6db6447b54728c538e987
動手前 2a74faf3df75aeed5002505fb102ad0b4259937e30f6db6447b54728c538e987
```

修完之後：

```
hooks.e2e    結果：29 通過，0 失敗，共 29 條
spec-v0.1    CONFORMS 33、VIOLATES 0、NOT_IMPLEMENTED 2、NOT_CHECKABLE 3
```

## 7. 測試本身的可靠度問題

pytest 那一半跑了兩次，結果不一樣：

```
第一次  2056 passed, 6 failed   346 秒
第二次  2068 passed, 0 failed   300 秒
```

第一次紅的六條全部在 `test_ui_render.py` 與 `test_ui_contract.py`，逐條單獨跑全部是綠的。原因是那幾條要開 Chrome，而第一次跑的時候我同時在跑 node 測試，資源競爭讓 Chrome 逾時。

這件事的意義不是「那六條沒事」，是「全套的結果會隨當下機器忙不忙而變」。所以往後引用「全套 N 綠」的時候，那個數字只有在單獨跑的條件下成立。

### 唯一的真缺口：Lineage Explorer

`apps/forseti-cli/lineage.py`（630 行）在，`summary()` 跑得動，回：

```json
{"count": 0, "ready_n": 6, "total": 10,
 "ready": ["CONSUMES","PRODUCES","PROPAGATES_TO","RECONSTRUCTED_FROM","SUPERSEDES","TRIGGERED_BY"]}
```

十種邊型別（v5.0 §6.3）裡六種備妥，實際帳本裡 0 筆，而且 `desktop/ui/app.js` 一處都沒有引用它。也就是說：寫出來了，沒有人寫資料進去，畫面也沒有入口。

這一支是 2026-09-18 才長出來的（它自己的檔頭寫著），所以「沒接上」是時間問題不是遺漏，但現在的狀態就是規格書 §16.1 八個視圖裡有一個是空的。

### 這一節驗不到的

這一節驗的是資料層。畫面層由 `tests/test_ui_render.py` 的 `ExpandedPagesMatchData` 以 Chrome dump-dom 驗（包含在 2068 passed 裡），而那支驗的是 DOM 有沒有畫出對的數字，不是像素長得對不對。
