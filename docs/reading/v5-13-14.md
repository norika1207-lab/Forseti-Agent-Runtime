## 一、這兩節規定了什麼

### §13 Behavioral Sequence Detection（379-391 行）

開頭那句是整節的立論（381 行）：

> Forseti evaluates sequences, not only isolated events.
> Several real failures are only visible across repeated turns.

**單看一個回合看不出來的東西，跨回合才看得見。** 七種模式，
每種都是「偵測草圖 + 對應動作」的形式（383-391 行）：

| # | 模式 | 偵測草圖 | 動作 |
|---|---|---|---|
| 1 | Thrashing | 同一資源被改 ≥ N 次，而且同一個錯誤簽章重複出現 | 暫停，強制換一個假設或做根因檢討 |
| 2 | Busywork / zero-change | 多次行動宣稱，但沒有對應的產物或程序變化 | 開一個 execution-honesty 事故 |
| 3 | Tool loop | 同一工具與動作重複，狀態沒有推進 | 凍結工具，進緊急對話模式 |
| 4 | Verification avoidance | verifier 要求證據之後，宣稱又重複一次 | 增加 trust debt，禁止升級為 canonical |
| 5 | Template degeneration | 回應相似度高，鷹架或開場重複 | 發布閘門，從證據重新生成 |
| 6 | Goal erosion | 小範圍的變異跨 session 累積 | 北極星 diff 加 clean fork |
| 7 | Premature completion | 在必要的驗證契約滿足之前就說 done | 完成閘門失敗 |

**第 7 條就是這整個專案的第一句話**（F01 的 TURN_END MUST NOT imply
TASK_END），在這裡它是七種行為序列模式裡的一種。

### §14 Backpressure, Freshness, and Pipeline Health（393-408 行）

立論在 395 行：

> A system can be "up" while becoming operationally dead.

十個要建模的流量指標（397-406 行）：

```
queue_depth              oldest_pending_age
input_rate / output_rate processing_lag
error_rate               retry_rate
last_successful_commit   evidence_freshness
model_latency            runtime_node_heartbeat
```

開 backlog 事故的三個條件（408 行）：佇列持續成長、最舊待處理項的
年齡越過政策門檻、或下游的新鮮度掉到工作流的 SLA 以下。

**而且最後那句話是重點：** even if every service returns HTTP 200。
每個服務都回 200，系統仍然可能已經死了。

## 二、對照 repo 現況

### §13 七種模式：JS 層有三種半，Python 主線零種

| 模式 | repo 現況 |
|---|---|
| Tool loop | **有。** `src/liveness.js:36` 的 `TASK_CLASSES` 含 `TOOL_LOOP`，判定在 `:203`。它自己標了 `thresholds_uncalibrated: true` |
| Verification avoidance | **有。** `src/progress.js:335` 起，判定結果是 `GOAL_RELEVANT_VERIFICATION_AVOIDANCE`（`:370`），檔內註明對應 CT-014 |
| Premature completion | **半個。** `src/yield.js` 是「過早交還發言權」，跟「過早宣稱完成」相關但不同；真正對應的是 `apps/forseti-cli/ledger.py` 的 VERIFYING 不等於 VERIFIED_COMPLETE，那是狀態機層的擋，不是序列偵測 |
| Goal erosion | **相關但不是它。** `src/drift.js` 是目標飄移、`src/goalanchor.js` 是北極星錨定，兩者都是單點判斷，沒有「跨 session 累積小變異」這個時間維度 |
| Template degeneration | **相關但不是它。** `src/rhetoric.js` 是信心詞與假坦白，看的是措辭不是相似度；沒有任何模組在算回應相似度 |
| Thrashing | **沒有。** 沒有任何地方在數「同一資源被改幾次」或比對錯誤簽章 |
| Busywork / zero-change | **沒有對應的模組。** 概念上最接近的是 `tools/classify-turns.mjs` 的 `UNSUPPORTED`（宣稱了具體物而前三輪零工具呼叫），但那是離線語料分析，不是執行期偵測 |

**一個對階段 4 影響很大的事實：** 上面所有「有」的東西都在 `src/`，
而 ADR-001 已裁定 `src/` 是離線參考實作、不是主線。照 v5.0 做階段 4
時這些要用 Python 重寫，JS 版當判準參考。這跟 `docs/reading/book-phase-3-6.md`
對 §12-15 的結論是同一件事。

### §14 十個指標：一個都沒有

22 個關鍵字全掃過，只有 `error_rate` 命中兩處，逐個開檔確認**都是誤命中**：
`tools/corpus-profile.mjs:132` 與 `tools/pick-negatives.mjs:97` 的
`tool_error_rate` 是離線語料統計的欄位，跟 pipeline 健康無關。

`queue_depth`、`oldest_pending_age`、`processing_lag`、`retry_rate`、
`last_successful_commit`、`evidence_freshness`、`model_latency`、
`runtime_node_heartbeat`、`backpressure`、`backlog` —— 全部沒有。

**這是合理的**：§14 建模的是一個持續運行的 pipeline，而現在的 Forseti
沒有 pipeline，只有離線分析加一本執行期帳本。ADR-003 裁定 hook 只採集、
daemon 才判斷，而 daemon 還沒做。

## 三、衝突與矛盾

### 一　`heartbeat` 同名不同義

`src/heartbeat.js` 的心跳是「前面所有機制都要有人來叫才會講話，
那等於把最後一道防線押在使用者記得問上面」（檔頭第 2-5 行），
也就是**主動報告**的機制。

§14 的 `runtime_node_heartbeat` 是**節點存活訊號**，用來判斷一個
runtime node 還在不在。

兩者都叫心跳，一個是「我主動說話」，一個是「我還活著」。做 §14 的時候
如果把 `heartbeat.js` 當成 `runtime_node_heartbeat` 的實作，會把
「有沒有主動報告」當成「節點活著沒」。

**這是第五個同名不同義**。前四個：`events`（待裁決第二條）、
`temperature`（`thermometer.js` 對 `signals.js`）、`rescue`
（`rescue.js` 檔名撞書但內容是別的）、lineage 邊型
（`topology.js` 九種對 §6.3 十種）。

**五個撞名不是巧合，是缺一份名詞表的症狀。**

### 二　§13 的動作欄要求的介入能力，主線目前沒有

七種模式的「動作」欄要求：暫停、開事故、凍結工具、增加 trust debt、
發布閘門、clean fork、完成閘門失敗。

`src/intervention.js` 有六種動作（`QUIET_ANNOTATION`、`SUGGEST_RECOVERY`、
`FREEZE_RETRY`、`REPLAN`、`BLOCK_HIGH_RISK`、`CREATE_SUCCESSOR`），
部分對得上（`FREEZE_RETRY` 對 tool loop 的凍結工具），但它在離線層。

Python 主線目前唯一有強制力的東西是 `ledger.py` 的狀態機與 verifier，
它擋得住「宣稱完成但驗不過」（第 7 種模式），擋不住其他六種。

**這不是漏做，是階段順序**：階段 4 才輪到健康與退化。記在這裡是因為
做階段 4 的人需要知道，七種模式裡有六種的動作端也要一起做，
不是只做偵測。

### 三　「evidence_freshness」與現有的證據觀念不在同一個維度

`src/evidence.js` 管的是證據的**等級**（OBSERVED / DECLARED / INFERRED /
MISSING，見待裁決第五條），§14 的 `evidence_freshness` 管的是證據的
**時效**。一份 OBSERVED 等級的證據可以是三天前的。

現在沒有任何地方記錄證據的時間有效性。做 §14 之前要先決定
freshness 是 evidence 的一個欄位，還是另一個維度的東西。
