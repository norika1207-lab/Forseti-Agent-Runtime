系統架構

五層。分工用一句話講：Main 擁有詮釋與驗收，Worker 擁有執行，Forseti 擁有持久的任務真相與連續性。

上下都是雙向：狀態往上報，指令往下走。

核心不變量：Turn completion is not Task completion。 對話生命週期不等於執行生命週期，Session 記憶不等於任務真相，模型自述不等於已驗證完成，心跳不等於進度。這四條各對應一次實際發生過的事故。

三條並行的線

它們處理三種不同的失效，所以分開走。合併會出現一個荒謬：用一個已經忘記北極星的 AI，去偵測自己有沒有偏離北極星。

一個任務怎麼走完

關鍵在兩個地方：報告不會推進狀態，宣稱完成只到 VERIFYING。

綠色回路是自動往下一步，紅色是驗證沒過退回重做。下排是報告路徑，它不碰狀態。

verifier 只支援兩種形式。 file:<path> 檔案存在且非空，cmd:<command> 指令 exit 0。刻意不支援由人或模型宣告通過的形式，那種東西就是 claim，而不信 claim 正是這個專案存在的理由。如果 verifier 可以用嘴巴過，「宣稱 done 但缺收據要維持非終止」那條測試就是假的，而假的驗證比沒有驗證更危險。

狀態機

十一種狀態，只有四種是終止。「我報告完了」不在其中。

VERIFYING 可以回到 RUNNING，驗證沒過要回去做，不是直接失敗。

停滯偵測怎麼算

四個因子相乘，每個 0 到 1。相乘的意思是任何一個接近 0 就足以洗掉懷疑。

STALL_RISK = duration_anomaly × no_progress_growth × no_event_activity × expected_progress_confidence
最右邊那個是關鍵煞車。如果這一步本來就不預期有可見產物（例如在等外部依賴），再久也不算停滯。沒有它，所有等待都會被誤判成卡住。這四個門檻全部沒有實測校準，規格只給了公式沒給值域。

把 F04 接上去

上一節第一項的解除記錄。過程比結論有用，因為結論只有一行，過程裡有兩個沒有人會發現的錯。

根因不是我懶得用它

動手第一件事是盤 CLI。七個命令，沒有一個碰得到 F03 到 F06。

除了單元測試以外，沒有任何東西呼叫得到 auto_dispatch()。不是我不用它，是沒有門可以進去。一個沒有入口的機制等於不存在。修法是補上 dispatch / auto / drain / event / verify / continuity 六個入口。其中 auto 特別處理了一件事：它回 None 有三種意思（任務已終止、沒有下一步、需要人決定），CLI 必須把三種分開講。安靜的 None 正是這整套東西要消滅的。

第一個錯：指標在用字串猜自己有沒有被用

auto = sum(1 for e in ev if e["kind"] == "DISPATCH"
           and "自動" in (e["cause"] or ""))

兩個方向都會錯。呼叫端自己給了 cause（例如「owner 已決定」）時，那一次真的自動派工會從指標裡消失；手動派工的理由裡只要寫到「自動」就會被誤算。而它會退化成猜字串，是因為 events_of() 的 SQL 根本沒有 SELECT payload，指標拿不到它要的欄位。

第二個錯：分母是 0，分數算出 3.0

接上之後第一次真的拿它跑一件真實任務，三步全自動走完，然後印出 3 / 0，分數 3.0。分數是比例，不該超過 1。

規格 F06 §5 只給了公式，沒有定義 ExpectedContinuation 數什麼。所以新的分母是我的詮釋，跟 STALL_RISK 的四因子同一個性質，已在 docstring 標明。

ExpectedContinuation = 「步驟驗證通過且任務還有下一步」的次數 + 進度報告次數
AutoContinued        = 自動派工次數，扣掉任務的第一次派工

扣掉第一次是因為那是起步不是接續，前面沒有東西可以接。不扣的話，一個只有一步的任務會看起來完美自動，而它從沒接續過任何東西。刻意不算 WORKER_RESULT：worker 交回結果之後的那次繼續，已經被「驗證通過就派下一步」涵蓋，兩邊都算會讓同一次交接被數兩次。

這兩個錯都只有在真的用它的時候才會出現。測試都走 submit_result() 那條路，而 drain() 不走。一個沒有人用過的指標，會安靜地算出離譜的數字。

三個最容易犯的錯

把中間結論當發現一個 1.6 倍的跨引擎差距，三輪清理之後歸零。每一個中間結論都比最終結論「有意思」，越像發現的東西越該多查一次。
讀到的是真的，歸納是假的讀 72 筆覺得「前一則幾乎都零工具」，量化之後 52.8% 對 47.9%，差距落在雜訊內。讀連續樣本沒有對照組會產生強烈但錯誤的模式感。
做出機制然後不用它目前最大的問題，而且它不會報錯。
