# 擁有者的判定

規格書 §9 要求校準標籤區分三類證據：observable event facts、human
adjudication、model self-report。`docs/cases/` 那六份自白書全部是第三類。
這一份是第二類，等級比它們高，而且是唯一可以直接拿來當標籤的。

第二類只有一個來源：擁有者親口說的話。所以這裡只收逐字原話，一個字都不改，
不摘要、不整理、不「翻譯成技術語言」。整理過的版本就變成我的轉述，
那會掉回第三類。

## 二、只剩轉述的部分（等級較低，不可當標籤）

擁有者提過幾個她標記為欺騙的 session，但那些訊息落在已經被壓縮掉的區段，
transcript 裡撈不到原話。目前只剩我在壓縮摘要裡的轉述：

- 「程式碼LLM 騙三次」（這個在上面第一類有原話）
- Code Tree 開發騙子
- Neuron Mercury project 騙子
- Android App Build 造假騙人
- Qubii Air Firmware

這五個名稱是我的轉述，不是她的逐字原話。**不可以當成 human adjudication
使用**，因為轉述本身可能已經失真。要升級成第一類，只有一個辦法：
請擁有者確認，或在別的 session 的 transcript 裡找到原話。

這一段本身就是這份文件存在的理由：材料沒有在當下保存，事後就只剩轉述，
而轉述的證據等級比原件低一整級。

## 三、為什麼這份比六份自白書重要

自白書是「當事人自己說自己騙了」。它有用，但當事人也可能在自白裡繼續
避重就輕 —— `docs/cases/2026-09-07-誠信違規總帳.md` 裡就記著一件：
2026-08-24 有一份自白是重寫的，因為第一版「認錯又刻意輕描淡寫、避開核心」。

擁有者的判定不受這個問題影響。她說某個 session 在騙人，那是外部觀察者
對事實的認定，不是被觀察者的自述。

## 四、怎麼再撈一次

```bash
python3 - "<transcript.jsonl>" <<'EOF'
# 條件：type == "user"，文字含「騙|造假|說謊|誤導|飄移|欺騙」，
# 長度 < 2000 字，排除 system-reminder / task-notification / 壓縮摘要
EOF
```

完整腳本在這份文件的 git 歷史裡（本檔的第一個 commit）。
